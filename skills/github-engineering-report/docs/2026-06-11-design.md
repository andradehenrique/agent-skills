# Design Document: github-engineering-report

## Skill Overview

A skill that generates comprehensive HTML engineering reports from GitHub data, optionally cross-referenced with Jira tickets. It produces daily/weekly panoramas, repository-specific summaries, or PR deep-dive timelines with analytical insights and human vs. automation classification.

## Skill Identity

- **name:** `github-engineering-report`
- **description:** Use when the user wants a daily or weekly engineering panorama, repository overview, or PR timeline analysis from GitHub, optionally cross-referenced with Jira tickets. Triggered by prompts about engineering summaries, repository activity, PR timelines, or what happened on a specific day/week.
- **type:** Technique / Workflow

## Goals

1. Provide a single-command way to get an actionable engineering report
2. Detect patterns and anomalies without manual spreadsheet work
3. Cross-reference GitHub activity with Jira tickets when relevant
4. Output a self-contained HTML file that can be shared anywhere

## Architecture

### Scope Extraction

The skill determines the report scope from the user's prompt:

- **Org-wide:** No specific repo mentioned, or mentions "engenharia", "time", "org"
- **Repo-specific:** Repo name mentioned (e.g., "auth-service", "frontend")
- **PR-timeline:** PR number or explicit "timeline" mentioned

### Time Window

- **Default:** Last 24 hours ("ontem")
- **Explicit:** Parse "esta semana", "últimos 7 dias", "desde segunda", etc.
- **Custom:** ISO dates if provided

### Data Flow

```
Prompt
  ↓
Scope Extractor → org / repo / PR
  ↓
Time Window → start_date, end_date
  ↓
GitHub MCP queries:
  - commits (since/until)
  - PRs (created/merged/updated in window)
  - issues (created/closed in window)
  - reviews (submitted in window)
  - comments (created in window)
  - actions/workflows (runs in window)
  - releases (published in window)
  ↓
Parser → extract Jira keys (ABC-123 pattern) from PR titles, commits, branches
  ↓
Jira MCP (if keys found) → ticket details, status, assignee
  ↓
Analyzer → apply heuristics (see below)
  ↓
HTML Generator → single self-contained HTML file
  ↓
Output
```

## Data Sources

### GitHub MCP

- **Required:** GitHub MCP configured with access to target org/repos
- **Queries:**
  - `list_commits` (per repo, filtered by date)
  - `list_pull_requests` (state=all, filtered by date)
  - `list_issues` (state=all, filtered by date)
  - `list_reviews` (for PRs in window)
  - `list_comments` (for PRs in window)
  - `list_workflow_runs` (for repos in window)
  - `list_releases` (for repos in window)

### Jira MCP

- **Optional:** Only if Jira keys detected in GitHub data
- **Queries:** `get_issue` for each detected key
- **Fallback:** If Jira MCP not available, note in report that Jira cross-reference was skipped

## Report Structure (HTML)

### Sections

1. **Header**
   - Title: "Panorama de Engenharia - {date_range}"
   - Scope: Org-wide / Repo: X / PR: #N
   - Generated at timestamp

2. **KPI Cards** (horizontal row)
   - Eventos (commits + PRs + issues + reviews + comments)
   - Commits
   - PRs abertos
   - PRs merged
   - Reviews
   - Comentários
   - Issues fechadas
   - Issues abertas
   - **Devs ativos/envolvidos** (count of unique authors across commits, PRs, and reviews)
   - Actions com falha
   - Releases

3. **Destaques / Análise** (color-coded cards)
   - PRs potencialmente bloqueados
   - Revisão humana vs. automação
   - PRs long-running
   - Features em andamento vs. bugfixes
   - Actions com falha
   - Releases/deploys
   - Anomalias detectadas

4. **PRs em Destaque** (table or cards)
   - PR #, Repo, Autor, Título, Status, Reviews, Comentários, Duração, Jira links

5. **Análise de Reviews**
   - Total reviews (humano vs. bot)
   - Top revisores
   - Reviews por PR
   - PRs merged sem review formal

6. **Cruzamento Jira** (if applicable)
   - Tabela: Ticket, Status, PRs vinculados, Progresso

7. **Contribuidores**
   - Lista de devs ativos, contagem de commits/PRs/reviews

8. **Timeline / Atividade Cronológica**
   - Lista ordenada de eventos principais com timestamp

9. **Footer**
   - Limitations disclaimer
   - Source: GitHub API + Jira API

### HTML Requirements

- **Self-contained:** All CSS inline, no external dependencies
- **Responsive:** Mobile-friendly with simple CSS grid/flexbox
- **Copy-paste ready:** Can be pasted into email/Slack as HTML
- **Sections collapsible:** Details/Summary HTML tags for long sections

## Heuristics (Analyzer)

### PR Bloqueado

- Open for > 3 days (default threshold), OR
- > 5 comments and no merge, OR
- Changes requested in latest review and no follow-up
- Note: Agent adapts threshold based on repo history if available

### Revisão Humana vs. Automação

- **Bots:** dependabot[bot], github-actions[bot], sonarqube[bot], etc.
- **Humans:** All other reviewers
- Report ratio and highlight PRs with only bot reviews

### PR Long-running

- Open for > 5 days
- Or: created in window but still open

### Feature vs. Bugfix

- **Feature:** PR title contains "feat", "feature", "add", "implement", or branch name (`head.ref`) starts with `feature/`
- **Bugfix:** PR title contains "fix", "bug", "hotfix", or branch name (`head.ref`) starts with `fix/`/`bugfix/`
- **Other:** Everything else

### Falha de Quality Gate

- PRs merged without a single human review
- Note: Some repos allow this via branch protection — flag as "direct merge" not "policy violation"

### Jira Orphan

- PRs with no Jira key in title, commits, or branch name

### Anomalias

- Spike in PRs opened but none merged
- Spike in issues opened
- Zero commits on a usually active repo
- Multiple failed actions in sequence

## Output Format

### Org-wide Report

- High-level KPIs across top 10 repos (by activity)
- Top 5 PRs em destaque
- Summary of Jira tickets touched
- Top 5 contribuidores

### Repo-specific Report

- All KPIs for that repo
- All PRs in window
- All issues opened/closed
- All releases
- Workflow run summary
- Timeline of events

### PR-timeline Report

- PR metadata (author, created, merged, branch)
- Timeline of all events (created, commits, reviews, comments, merge)
- Review details (who, when, what)
- Comment thread highlights
- Jira ticket details (if linked)
- Files changed summary
- Verdict: "Healthy", "Blocked", "Long-running", "Hotfix"

## Edge Cases

- **No activity:** Report shows "Nenhuma atividade detectada no período" with a smiley
- **Large org:** If > 10 repos, show top 10 by activity, mention "+N outros repos"
- **Jira unavailable:** Section omitted with note
- **Private repo without access:** Note "Repositório privado — verifique permissões do MCP"
- **Rate limited:** Retry with backoff, or report partial data with note
- **Draft PRs:** Include in counts but flag as "draft" in PR listing

## Error Handling

- If GitHub MCP returns error: Report error in HTML header with suggestion to check token
- If Jira MCP returns error: Skip Jira section, continue with GitHub data
- If no data found: Generate report with zeroed KPIs and friendly message
- If partial failures: Include note about what couldn't be fetched

## Future Enhancements (out of scope for v1)

- Weekly trend comparison (vs. previous week)
- Slack/Discord webhook integration
- CSV/JSON export option
- Historical chart with Chart.js
- Team-specific filters (frontend, backend, etc.)

## Open Questions

- Should we cache previous reports to enable trend analysis? (Not for v1)
- Should we integrate GitHub Actions artifacts or just run status? (Just status for v1)

## Dependencies

- GitHub MCP configured with `repo` scope
- Jira MCP configured (optional)
- Opencode agent with access to both MCPs

## Success Criteria

- User can say "Dá o panorama de ontem" and get a complete HTML report in < 60s
- User can say "Resumo do repo auth-service" and get repo-specific report
- User can say "Timeline do PR #234" and get PR deep-dive
- Report is self-contained and shareable without extra dependencies
- Report correctly distinguishes human vs. bot reviews
- Report flags anomalies and blockers without false positives
